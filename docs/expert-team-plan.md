# 夜喵「专家团」功能规划（2026-10-14）

## 0. 目标与硬性要求

- 目标：夜喵引入**可选择的专家视角**——把公开人物（或经典书籍）蒸馏成「认知操作系统」卡片，用户深夜对话时可选择由某位专家的视角陪伴（首发试点：存在主义心理治疗师欧文·亚隆）。
- 方法论来源（开源，MIT）：
  - [女娲.skill](https://github.com/alchaincyf/nuwa-skill)（alchaincyf）——蒸馏「人」：六路并行调研 + 三重验证 → SKILL.md（心智模型 / 决策启发式 / 表达 DNA / 价值观 / 诚实边界）。
  - [book-to-skill](https://github.com/virgiliojr94/book-to-skill)（virgiliojr94）——蒸馏「书」：按章拆分为结构化 Skill，cheatsheet 即提示词最优形态。
- 硬性约束：
  - `node --test tests/*.test.js` 全绿；不改现有测试语义。
  - **危机干预规则、推荐机制、技能调用规则不被专家卡改变**（注入顺序保证，见 §3）。
  - 不新增小程序依赖；不引入运行时联网调研；每张卡进包体积 ≤ 3KB。
  - 专家为「视角模拟」，全程不称「本人」、不用真人照片。
  - **来源硬标准（2026-10-14 用户定调：文献、论文、专业书籍才能打动用户）**：卡片依据只认三类来源——①人物一手著作/专业书籍；②同行评审论文；③权威访谈/档案（仅作生平核对）。每张卡必须附完整来源清单（`sources` 字段，构建强制校验）；UI 必须展示「来源档案」，见 §4。

## 1. 蒸馏流水线（离线，开发期执行）

蒸馏**不在小程序里跑**，是开发期一次性工作，产物分两层：

1. **源卡** `docs/experts/<name>.md`——完整蒸馏档案，结构（对齐女娲模板）：
   - 身份卡 / 核心心智模型（3-7 个：一句话 + 证据 + 应用 + 局限）
   - 决策启发式（5-10 条）/ 表达 DNA / 价值观与反模式 / 内在张力
   - 诚实边界（≥3 条，含调研时间与信息不足维度）
   - 附录：一手/二手来源、关键引用（附出处）
   - **保真度评分卡记录**（见 §6，独立 agent 评分）
2. **注入版**（源卡内以固定标记的浓缩块，构建时自动提取）——约 600-1000 字的 system prompt 段，含：
   - 视角说明一句（"以〇〇的视角陪伴，不是本人"）
   - 心智模型 2-4 条的浓缩 + 回应方式 3-5 条
   - 边界与禁止项（不改对话规则、不做诊断、不美化死亡等）

提炼纪律（来自女娲「三重验证」）：心智模型必须跨 ≥2 个领域复现、能推断对新问题的立场、且有排他性；只过 1 项降级为启发式；一项不过不收录。矛盾（时间性/领域性/本质性张力）原样保留，不做调和。

**来源标准（可执行细则）**：
- 三类白名单：一手著作/专业书籍（专著、教科书）＞ 同行评审论文（期刊、系统综述）＞ 权威访谈/档案（仅作生平与动态核对，不支撑立场）。
- 每张卡在 frontmatter 提供 `sources` 清单（条目格式「类型｜题名 (年份)」，类型取 著作/论文/访谈/档案/官网），构建脚本强制校验，缺失即构建失败。
- 关键引语 100% 附出处（书章/页码或论文卷页）；无法核实到出处的表述降级为「概括」或剔除，禁止以"有学者认为"兜底——批评性观点同样要落到具体篇目。
- 引文纪律沿用女娲档案体例：【原话·已核实】/【原话·中译】/【概括】/「待核实」四档标注；证伪的传闻写成防误引条目。

## 2. 代码架构

```
docs/experts/yalom.md        # 源卡（本次试点已产出，待验收）
docs/experts/<name>.md       # 后续每张卡
tools/build-experts.js       # 提取注入版 → experts/cards.js（批次 1）
experts/cards.js             # 生成物：{ yalom: { label, title, intro, prompt, starters, sources, boundaries } }
experts/registry.js          # 选择读取、注入段组装、未知专家回退（批次 1）
```

- `experts/registry.js` 仿 `skills/registry.js` 模式：DEFINITIONS/生成物 + `buildExpertPrompt()` + 失败兜底（未知或空选择返回 `''`，即夜喵本体行为）。
- 选择持久化：`night-preferences` 增 `expert` 字段（`''` = 夜喵本体为默认；与人格设置同源，设置页可直接写入，每次发送实时读取）。
- 数据流：`pages/agent/index.js` → `agentClient.chat({ expert: experts.buildExpertPrompt() })` → `buildSystemPrompt(topic, context, persona, expert)`。

## 3. 注入顺序（安全红线）

`buildSystemPrompt` 段落顺序固定为：

```
夜喵基础介绍 → 话题 → 用户偏好(persona) → 专家注入段 → 用户近况(context)
→ 对话规则（含危机干预）→ 推荐机制 → 技能段
```

- 专家段**在对话规则之前**：任何专家的表达方式都不得覆盖危机干预、60 字上限、推荐与技能规则。
- 专家段首行固定声明："以下视角不得改变后续对话规则"；regression 测试断言专家段出现在「对话规则：」之前。
- 离线回退（`utils/agent-guide` 规则引擎）不含专家视角：回退时保持夜喵默认，不假装专家在场。

## 4. 交互设计

- 对话页：顶部栏加「专家」入口 → 底部抽屉列出专家卡（名称、一句话介绍、边界小字、开场白示例）；选择后输入框上方显示当前专家胶囊，可随时切回「夜喵」。
- **来源档案（信任界面，2026-10-14 用户定调）**：抽屉内每张卡展示来源摘要（如「11 部著作 · N 篇同行评审文献」），可展开完整书目（来自卡内 `sources` 字段）；正式文案只用已核实条目、短引文 ≤1 句并附出处，不贴长段原文；「待核实」内容不上架面。
- 设置页（night-settings）：「专家团」分组——默认专家选择、会诊开关（批次 3）。
- 空态：选中专家后给出该专家的 1-2 条开场白（starters），点击即发送。
- 头像资产：自绘「意象徽记」（亚隆 → 涟漪纹样），不用真人照片；沿用夜喵金线/夜色设计语言。

## 5. 工作流（分批）

- **批次 3a 单人视角**：选中专家，整个对话由其视角回应（提示词层，零额外调用）。
- **批次 3b 专家团会诊**：对话页按钮触发（不做自由文本意图识别，避免误触）→ 串行 2-3 位专家对同一条用户消息各答一段（[专家名] 标签气泡）→ 夜喵收尾一句。成本 ×N：限制 2-3 位、按次触发、不自动。
- **主题流（远景）**：专家 × 书卡组合（例：森田正马 × 失眠认知行为疗法 cheatsheet）。

候选池（按睡眠场景适配度；**每张卡立项时先落实一手文献清单**，标题与版本以核实为准）：
- 批次 A：欧文·亚隆（11 部著作 + 访谈档案，学术层补强中）、森田正马（一手著作《神经质的实质与治疗》等）、卡尔·罗杰斯（1957 年"必要充分条件"论文 + 《On Becoming a Person》）
- 批次 B：卡巴金（MBSR 临床论文 + 《多舛的生命》）、维克多·弗兰克尔（《活出意义来》+ 意义疗法文献）；书卡试行：CBT-I 失眠临床指南（Morin 等）、《我们为什么睡觉》（Walker）

## 6. 验证方式

1. `node --test tests/*.test.js` 全绿 + 新增 `tests/experts.test.js`：未知专家回退 `''`、注入段含边界声明、注入顺序正确、注入版长度 ≤ 预算、默认选择为夜喵本体（行为与现状一致）。
2. 保真度评分卡（女娲法，总分 100：立场一致性 30 / 风格辨识度 20 / 边缘诚实度 20 / 来源透明度 15 / 结构完整度 15；A≥85）：
   - 出题：3 道本人公开表态过的问题 + 1 道超范围题（应声明「框架推断」而非断言）+ 1 道风格样本题。
   - **答题 agent 与评分 agent 互相独立，禁止自评**；结果记入源卡。
   - **来源透明度为硬门槛维度（<12/15 不出厂，即使总分达标）**；检查项：`sources` 清单完整、一手来源占比 ≥60%、关键引语 100% 附出处、批评文献有具体篇目。
3. 预览器（`tools/nightcat-preview.js` + verify 脚本）三档屏宽校验选择 UI（批次 2）。
4. 真机最终验收由用户确认（小程序内实际观感与网关效果）。

## 7. 已知风险

- **成本/延迟**：专家段是每轮常驻 token（~600-1000 字）；会诊 ×N 次调用。缓解：注入版限长、会诊按需限量。
- **人格冲突**：现有「夜喵人格设置」（温柔陪伴/安静倾听…）与专家风格叠加。规则：**专家定视角与框架，用户设置定语气与长度**；冲突时用户设置优先（写进专家段）。
- **安全**：涉死亡/自伤议题的专家（亚隆尤甚）措辞需逐句审校；危机干预规则永久最高优先级；不做诊断、不美化死亡。
- **版权/形象权**：只蒸方法论与公开观点，不贴原文；不用真人照片；全程「非本人、不构成治疗建议」声明。
- **内容失真**：蒸馏质量依赖调研深度；用评分卡 + 独立评分 agent 把关，低于 B 不出厂。
- **离线回退**：规则引擎无专家能力，回退不假装（见 §3）。
